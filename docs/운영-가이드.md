# ARMES 홈페이지 운영 가이드

> 작성일: 2026-06-24 · 적용: 즉시
> 이 문서는 **운영 방침**입니다. 코드가 아니라 "앞으로 어떻게 운영할지" 약속을 적어 둔 메모입니다.

---

## 0. 한 줄 요약

**콘텐츠/SEO 대공사는 끝. 지금 상태를 동결한다. 앞으로는 "서비스에 실제 변화가 생길 때만 News 한 편"을 올리고, 구글 검색 데이터(GSC)를 1주·2주·1개월 간격으로 관찰한다.**

## 1. 운영 대원칙 (절대 기준 — 가장 먼저 읽을 것)

> 아래 4개는 **이 문서의 모든 판단보다 위에 있는 기준**입니다. 새 세션이든 누구든, 무언가 "더 하고 싶어질 때" 이 항목과 부딪히면 **멈춥니다.**

- 🚫 **SEO 구조 추가 공사 금지** — sitemap 재설계, canonical/도메인 통일, JSON-LD 개편 등 구조 손대기 안 함.
- 🚫 **블로그 대량 생산 금지** — 검색량만 보고 글 수 늘리지 않음.
- 🚫 **GSC 데이터 없이 구조 변경 금지** — 감으로 고치지 않음. 최소 1개월 데이터부터 본다.
- ✅ **현재 상태를 "기본선"으로 유지** — 지금 배포된 모습이 정상 기준선. 바꾸려면 데이터 근거가 먼저 있어야 한다.

> 한 줄: **"기본선을 지킨다. 데이터가 말하기 전엔 구조를 건드리지 않는다."**

## 2. 현재 상태 동결 (대공사 종료)

블로그 48편 전부 장문화 완료, 서비스 SEO·sitemap·구조화 데이터까지 깔아 둔 상태입니다. 여기서 **멈춥니다.**

### 하지 않는 것 (중단)
- ❌ 블로그 글 대량 생산 (신규 카테고리·대량 작성)
- ❌ SEO 구조 대공사 (sitemap 재설계, canonical/도메인 통일, JSON-LD 추가 개편 등)
- ❌ 기존 글을 "점수 올리려고" 다시 갈아엎기

> 이유: 인프라는 충분히 깔렸습니다. 지금은 **구글이 우리 글을 평가하는 시간**이 필요합니다. 데이터도 없이 더 손대면 100점 노리다 70점 됩니다. 일단 둡니다.

### 유지하는 것
- ✅ 지금 배포된 블로그·서비스 페이지 그대로 둔다
- ✅ www/non-www 도메인 구조도 **그대로 동결** (건드리지 않음)
- ✅ 오타·깨진 링크·사실 오류 같은 **명백한 버그만** 그때그때 수정

## 3. News 운영 (회사 활동 기록)

블로그는 멈추지만, **News는 계속 누적**합니다. News는 SEO용 글이 아니라 **"회사가 실제로 무슨 일을 했는지" 기록하는 활동 일지**입니다.

### News는 2종으로 나눈다 (중요)

큰 사건만 기다리면 DUNS 대기 같은 긴 침묵 동안 News가 비어 "멈춘 회사"처럼 보입니다. 그래서 News를 **2종**으로 나눠, **"살아있는 서비스 회사"라는 신호를 꾸준히 남깁니다.**

| 종류 | 성격 | 빈도 | 해당 사건 |
| --- | --- | --- | --- |
| **① 마일스톤 News** | 누가 봐도 큰 사건. 무겁게. | 생길 때마다 | 앱 출시 · 스토어 등록 · 제휴 · MAU 달성 · 대형 기능 추가 |
| **② 개발 노트** | "우리 이렇게 일하고 있다" 신호. 가볍게. | **월 1~2편 수준 권장** | DUNS 진행 · 데이터 연동 완료 · OCR 개선 · 기능 추가 · 개발 진척 |

#### 개발 노트 작성 시 반드시 지킬 것
- ✅ **실제 발생한 사실만** 쓴다.
- 🚫 **과장 금지** (검증 안 된 수치·성과 부풀리기 X).
- 🚫 **미래 약속 금지** ("곧 출시합니다" X → 이미 일어난 일만).
- ⏱️ **월 1~2편 수준** 권장 (너무 잦으면 오히려 가벼워 보임).

### 언제 올리나
**서비스/기능에 실제 진척이 생겼을 때만.** 억지로 만들지 않습니다. 진짜 변화가 있을 때 한 편. (마일스톤이 없으면 위 ② 개발 노트로 생존 신호를 남긴다.)

| 서비스 | News 올릴 상황 예시 |
| --- | --- |
| ARMES Tools | 개발 현황, 도구 추가(PDF·이미지 변환 등) 공개 |
| RewardTalk | 기능 추가, 가맹점 연동, 베타 오픈 |
| TravelMoa | 준비 현황, 항공권·특가 연동 진척 |
| CocoPing | 업데이트, 신규 기능 |
| SellerAI | 개선 사항, 신규 AI 기능 |
| 회사 전체 | 방향 정리, 제휴, 수상·인증 등 |

### 어떻게 올리나 (작성법)
1. `content/news/` 폴더에 새 파일을 만든다. 파일명은 영문 소문자+하이픈 (예: `armes-tools-progress.md`).
2. 아래 frontmatter 템플릿을 맨 위에 넣고 본문을 쓴다.
3. 저장하고 커밋·푸시하면 자동으로 News 목록 **맨 위(최신순)**에 뜬다. (정렬은 `date` 기준 자동)

#### frontmatter 템플릿
```markdown
---
title: (제목 — 무엇을 했는지 한 줄)
date: 2026-07-01
updated: 2026-07-01
category: 서비스 소식
excerpt: (목록에 보일 2~3줄 요약)
thumbnail: /blog/covers/(이미지파일).png
imageAlt: (이미지 설명)
tags: [회사 소식, (서비스명), (키워드)]
---

(본문 — 마크다운)
```

- `category` 예시: `공지`, `서비스 출시`, `서비스 소식`, `개발 현황`
- `thumbnail`은 없으면 기존 커버 중 어울리는 것 재사용 가능
- **길이 부담 없음**: 블로그처럼 5,000자 안 채워도 됩니다. 활동 기록이라 **사실 위주로 짧고 정확하게**면 충분합니다.

### News 작성 원칙 (중요)
- **사실만.** 아직 안 된 기능을 "출시했다"고 쓰지 않는다. 준비 중이면 "준비 중"이라고 쓴다.
- 날짜를 정확히. `date`가 노출 순서를 정한다.
- 과장·광고 문구 금지. 담담한 활동 기록 톤.

## 4. 블로그 운영 원칙 (검색량 중심 → 서비스 지원 중심)

지금까지 블로그는 **"사람들이 많이 검색하는 키워드"**를 좇았습니다(검색량 중심). 문제는 그렇게 들어온 사람이 글만 읽고 나가면 **회사엔 남는 게 없다**는 점입니다.

앞으로는 방향을 바꿉니다. **검색으로 들어온 사람을 우리 서비스로 데려가는 글**만 씁니다(서비스 지원 중심).

### 절대 기준 (새 글 작성 전 자가 점검)
> **"이 글이 어느 서비스로 연결되는가?"**
> 이 질문에 **답이 없으면 작성하지 않는다.**

- 답이 있으면(예: "주유 할인 글 → RewardTalk") → 작성 검토.
- 답이 없으면(그냥 검색량 많아서) → **작성하지 않는다.**

### 서비스별 받침 콘텐츠 매핑 (출시 시 가동)

| 서비스 (출시·기능 추가 시) | 받쳐줄 블로그 주제 |
| --- | --- |
| **RewardTalk** | 주유 할인 · 전기차 충전 · 동네 상권/지역 멤버십 |
| **TravelMoa** | 여행 특가 찾는 법 · 항공권 싸게 사는 법 |
| **CocoPing** | 코스트코 할인 정보 · 코스트코 알뜰 구매 |
| **SellerAI** | 상세페이지 만드는 법 · 상품 이미지 잘 찍는 법 |

> 참고: 전기차·주유·지역상권 글은 **이미 블로그에 깔려 있습니다.** 새로 많이 만들지 말고, **출시 타이밍에 기존 글의 CTA(서비스로 가는 버튼)만 점검·보강**하는 것이 우선입니다. → [1. 운영 대원칙]의 "블로그 대량 생산 금지"와 충돌하지 않습니다.

## 5. GSC(구글 서치 콘솔) 관찰 체크리스트

지금부터 할 일은 **글쓰기가 아니라 "지켜보기"**입니다. 씨를 다 뿌렸으니, 싹이 어떻게 나는지 관찰하는 단계입니다.

- 관찰 대상: **GSC 도메인 속성 `armes.co.kr`** (이미 인증·sitemap 제출 완료)
- 제출한 sitemap: `https://www.armes.co.kr/sitemap.xml` (약 75페이지)
- 보는 곳: [search.google.com/search-console](https://search.google.com/search-console)

> 핵심: **숫자 하나하나에 일희일비하지 말 것.** 검색 노출은 원래 몇 주~몇 달 걸립니다. 아래 3개 시점에 "큰 흐름"만 봅니다.

### ① 1주 후 — 2026년 7월 1일경 · "색인이 시작됐나"
이 시점 목표: 구글이 우리 사이트를 **발견하고 읽기 시작했는지** 확인.

| 확인 항목 | GSC 메뉴 | 정상 신호 |
| --- | --- | --- |
| sitemap 처리 상태 | 색인 > Sitemaps | "성공", 발견된 페이지 수 표시 |
| 색인된 페이지 수 | 색인 > 페이지 | 색인 생성됨 0 → 조금씩 증가 시작 |
| 크롤링 시작 여부 | 설정 > 크롤링 통계 | 구글봇 방문 기록 존재 |
| 심각한 오류 없는지 | 색인 > 페이지(이유별) | robots 차단·서버오류 같은 치명 오류 0 |

→ 아직 노출·클릭이 0이어도 **정상**입니다. 이 시점은 "읽기 시작했다"만 확인.

### ② 2주 후 — 2026년 7월 8일경 · "노출이 시작됐나"
이 시점 목표: 검색 결과에 **우리 글이 보이기 시작**하는지 확인.

| 확인 항목 | GSC 메뉴 | 정상 신호 |
| --- | --- | --- |
| 색인 페이지 수 추이 | 색인 > 페이지 | 1주차보다 증가 |
| 첫 노출(Impressions) | 실적 > 검색결과 | 0 → 발생 시작 |
| 어떤 검색어로 보이나 | 실적 > 쿼리 탭 | 검색어 목록 등장 시작 |
| 어떤 글이 먼저 잡히나 | 실적 > 페이지 탭 | 노출되는 URL 확인 |

→ 클릭은 아직 적을 수 있음. **"노출이 생겼다"**가 이 시점 합격선.

### ③ 1개월 후 — 2026년 7월 24일경 · "다음 방향을 정한다"
이 시점 목표: 실제 데이터로 **다음에 뭘 할지 판단**.

| 확인 항목 | GSC 메뉴 | 무엇을 보나 |
| --- | --- | --- |
| 노출·클릭 추이 | 실적 > 검색결과 | 늘고 있나 / 정체인가 |
| 평균 게재순위(Position) | 실적 > 검색결과 | 몇 위권인가(20위 안이면 좋음) |
| 클릭률(CTR) | 실적 > 검색결과 | 노출 대비 클릭 비율 |
| **유입 키워드 TOP** | 실적 > 쿼리(클릭순 정렬) | 실제로 들어온 검색어 10~30개 |
| 강한 글/약한 글 | 실적 > 페이지 | 어떤 글·카테고리가 잘 되나 |
| 기기 비율 | 실적 > 기기 | 모바일 vs PC |

#### 1개월 후 의사결정 기준
- 특정 키워드/글이 **노출은 되는데 순위가 낮다** → 그 글만 **콕 집어** 보강 (대량 생산 아님)
- 특정 카테고리가 **유독 잘 된다** → 그쪽으로만 선택적 확장 검토
- **거의 안 잡힌다** → 더 기다린다(2~3개월). 섣불리 구조 안 건드림
- 어느 경우든 **"데이터가 가리키는 곳만"** 움직인다. 감으로 대량 생산하지 않는다.

## 6. 6개월 운영 로드맵 (구축 단계 → 운영 단계)

지금이 **구축(공사) 끝 → 운영(장사) 시작**의 전환점입니다. 비유하면 **인테리어 다 끝낸 가게의 문을 여는 단계**입니다. 6개월을 3구간으로 나눕니다.

### 🟦 1~2개월차 — 관찰 단계 (지금)
**핵심 한 단어: 관찰**

- 해야 할 것
  - GSC를 1주·2주·1개월 시점에 관찰 (→ [5. GSC 체크리스트])
  - 마일스톤 없으면 **개발 노트**로 생존 신호 (월 1~2편)
  - DUNS 풀리는 순간 = 출시 News + 해당 서비스 콘텐츠 CTA 점검
- 하지 말아야 할 것
  - 🚫 블로그 신규 작성 (동결 유지)
  - 🚫 SEO 구조 공사
  - 🚫 숫자 0이라고 조급해하기 (검색 노출은 원래 몇 주~몇 달 걸림)

### 🟩 3~4개월차 — 핀셋 보수 단계
**핵심 한 단어: 핀셋**

- 해야 할 것
  - 1개월 데이터로 **효자 글 / 문제 글 구분**, 11~20위 글만 콕 집어 보강
  - 출시 발생 시 서비스별 받침 콘텐츠 가동 (→ [4. 블로그 운영 원칙] 매핑)
  - 노출 많은데 클릭 적은 글 → 제목·설명(메타)만 손봄
- 하지 말아야 할 것
  - 🚫 대량 생산
  - 🚫 구조 변경
  - 🚫 검색량만 보고 글쓰기 (서비스 연결 없는 글 X)

### 🟨 5~6개월차 — 선택과 집중 단계
**핵심 한 단어: 집중**

- 해야 할 것
  - 3개월 추세 판단 → **우상향이면 구조 유지** + 되는 카테고리만 강화
  - 블로그 유입 → 실제 서비스 가입/사용 연결 점검 (안 되면 내부링크·CTA만 수정)
  - 실제 숫자가 쌓이면 "출시 후 N개월 성과" 같은 마일스톤 News
- 하지 말아야 할 것
  - 🚫 멀쩡한 구조 갈아엎기
  - 🚫 죽은 카테고리 때문에 전체 손대기 (그 카테고리만 선택 보수)

| 구간 | 핵심 | 해야 할 것 | 하지 말 것 |
| --- | --- | --- | --- |
| 1~2개월 | 관찰 | 개발노트 News, GSC 관찰 | 블로그 신규, SEO 공사 |
| 3~4개월 | 핀셋 | 효자글 보강, 출시 연동 | 대량 생산, 구조 변경 |
| 5~6개월 | 집중 | 되는 것 강화, 연결 점검 | 구조 갈아엎기 |

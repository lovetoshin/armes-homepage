做开发或处理数据时，经常会遇到 `aHR0cHM6Ly9hcm1lcy5jby5rcg==` 这样**看不懂的长字符串**。有时还会收到"请将此值进行 Base64 编码后发送"的说明。初看像密码，但理解原理之后会发现，其实简单得让人有点意外。

Base64 是**一种将任何数据都用几十个英文字母和数字重新表示的方法**。本文将用非技术人员也能看懂的语言，解释 Base64 究竟是什么、为什么使用，并通过实际示例说明编码与解码，澄清最常见的误解（不是加密！），以及安全使用的方法。

## Base64 是什么

Base64 是一种将图片、文件等**非文字数据（二进制数据）转换为文本字符串**的方法。它只使用英文大小写字母（A–Z、a–z）、数字（0–9）以及 `+`、`/` 两个符号——共 **64 个字符**，因此得名 Base64。

打个比方：就像为了安全地通过邮寄发送任何物品，**将其重新装进标准尺寸的纸箱**一样。内容物不变，只是把外观换成任何地方都能无障碍传递的形式。

## 编码前后 — 实际示例

**原始文本 → Base64（编码）：**

```text
原始 :  ARMES
Base64 :  QVJNRVM=
```

```text
原始 :  你好
Base64 :  5L2g5aW9
```

反过来，将 `QVJNRVM=` **解码**，就能还原为 `ARMES`。末尾的 `=` 是用于补齐长度的**填充符号**。

## 编码与解码

| 类别 | 方向 | 示例 |
| --- | --- | --- |
| 编码（Encode） | 原始数据 → Base64 | `ARMES` → `QVJNRVM=` |
| 解码（Decode） | Base64 → 原始数据 | `QVJNRVM=` → `ARMES` |

在在线工具中输入原始内容，即可得到编码结果；输入 Base64 字符串，即可立即得到解码结果。

## 为什么使用 — 实际使用场景

数据传输通道中，很多情况下**只能安全传递文字（文本）**。直接发送图片等非文字数据可能导致内容损坏，因此先将其转换为"类似文字"的形式再发送。

| 使用场景 | 原因 |
| --- | --- |
| 电子邮件附件 | 旧版邮件协议只能安全传输文本 |
| 网页内联图片 | 将小图标不借助外部文件直接嵌入代码（Data URL） |
| API 令牌传输 | 通过 `Authorization` 等请求头以文本形式传递 |
| JSON 中嵌入文件 | JSON 是文本格式，文件需先转换为 Base64 嵌入 |

## ⚠️ 最常见的误解 — Base64 不是加密

这是本文**最重要的部分**。

| 误解 | 事实 |
| --- | --- |
| "转换为 Base64 就安全地隐藏了数据" | ❌ 任何人 1 秒内即可解码 |
| "用 Base64 存储密码就安全了" | ❌ 与明文存储没有区别 |
| "它是一种加密方式" | ❌ 只是**表示形式的转换**而已 |

Base64 不是锁，而是**透明的包装纸**。任何人都可以打开查看内容。**认为"用 Base64 就能安全隐藏"是非常危险的想法。**真正需要安全保护时，必须使用加密技术（哈希、AES 等）。

## 需要了解的几点

- **数据大小会增加约 33%。**原始 3 个字节的数据会变成 4 个 Base64 字符。小数据问题不大，但大文件需要注意。
- **有 URL 安全版本。**`+`、`/` 在 URL 中会产生问题，URL 安全的 Base64 会将其替换为 `-`、`_`。
- **注意敏感数据：**包含令牌或密钥的数据，请在**仅在浏览器内部处理**的工具中操作，不要上传到服务器。

## 总结

Base64 是**将任何数据重新打包为文本以便安全传输**的方法。编码转换，解码还原，就是这么简单。记住一件事：**Base64 是包装，不是加密。**理解了这个概念，再遇到看不懂的字符串就不会慌张了。

## 常见问题（FAQ）

**Q. Base64 用一句话来说是什么？**
将图片、文件等非文字数据用 64 个英文字符表示，使其能像普通文本一样处理的方法。

**Q. 用 Base64 编码数据后数据会变安全吗？**
不会。任何人都可以立即解码，没有任何安全效果。需要安全保护时，必须使用加密技术。

**Q. 末尾的 `=` 符号是什么？**
用于将总长度补齐为 4 的倍数的填充符号。根据原始数据的长度，可能出现 0～2 个。

**Q. 编码后数据大小为什么会增加？**
因为原始 3 个字节会表示为 4 个 Base64 字符，大小增加约 33%。在大文件中嵌入 Base64 时需要考虑这一点。

**Q. 在 URL 中放了 Base64，结果乱码了。**
普通 Base64 中的 `+`、`/` 符号在 URL 中会引起问题，请改用以 `-`、`_` 替代的 URL 安全 Base64。

**Q. 中文也能进行 Base64 编码吗？**
可以。中文通常先通过 UTF-8 转换为字节，再进行编码。解码时编码方式（UTF-8）必须一致，否则会出现乱码。

**Q. 可以用 Base64 存储密码吗？**
绝对不行。与明文存储没有区别。密码必须使用哈希（如 bcrypt）处理。

**Q. 可以在在线 Base64 工具中输入敏感数据吗？**
如果该工具会将输入发送到服务器，则不行。令牌和密钥请使用仅在浏览器内部处理的工具。

링크를 복사했더니 주소에 "%20", "%EC%95%88" 같은 이상한 문자가 잔뜩 섞여 있던 경험, 있으실 겁니다. 또는 한글이 들어간 주소가 깨져서 안 열린 적도 있을 것입니다. 이 모두가 **URL 인코딩**과 관련된 일입니다. 이 글에서는 URL 인코딩이 무엇이고 어떻게 해결하는지 쉽게 정리합니다.

## URL 인코딩이란

웹 주소(URL)에는 **쓸 수 있는 문자가 정해져** 있습니다. 영문, 숫자, 일부 기호만 안전하게 통하고, 공백·한글·특수문자는 그대로 쓸 수 없습니다. 그래서 이런 문자를 **안전한 형태로 바꾸는 것**이 URL 인코딩입니다.

예를 들어 공백은 "%20"으로, 한글 "안"은 "%EC%95%88" 같은 형태로 바뀝니다. 이상해 보이지만, 주소를 어디서든 깨지지 않게 전달하기 위한 약속입니다.

## 인코딩과 디코딩

- **인코딩:** 사람이 읽는 주소(한글·공백 포함) → 안전한 주소(%형태)
- **디코딩:** %형태로 인코딩된 주소 → 사람이 읽는 원래 주소

온라인 도구에 주소를 넣으면 인코딩·디코딩 결과를 바로 보여 줍니다. "%" 범벅인 주소가 무슨 뜻인지 확인할 때 디코딩이 유용합니다.

## 언제 필요한가

- **링크 공유:** 한글·공백이 든 주소를 메신저나 메일로 보낼 때 깨지지 않게
- **검색·파라미터 처리:** 검색어를 주소에 담을 때
- **개발 작업:** API 요청 주소에 값을 넣을 때

## 알아두면 좋은 점

- **두 번 인코딩 주의:** 이미 인코딩된 주소를 또 인코딩하면 "%25..."처럼 더 깨집니다. 한 번만 하세요.
- **한글 주소:** 요즘 브라우저는 한글 주소를 자동으로 처리해 주지만, 외부로 전달할 때는 인코딩이 안전합니다.

비슷하게 데이터를 다루는 [Base64 인코딩·디코딩 쉽게 이해하기](/blog/base64-guide)와 [JSON 포맷(정리)하는 법](/blog/json-format)도 함께 보면 좋습니다. 전체 개발용 도구는 [개발자용 온라인 도구 모음](/blog/dev-tools)에 모아 두었습니다.

## 정리

URL 인코딩은 **주소에 쓸 수 없는 문자(공백·한글·특수문자)를 안전한 형태로 바꾸는** 약속입니다. 깨진 주소는 디코딩으로 원래 모습을 확인하고, 공유할 주소는 인코딩으로 안전하게 만들면 됩니다. 두 번 인코딩만 피하면 어렵지 않습니다.

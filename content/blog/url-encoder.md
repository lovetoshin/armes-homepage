링크를 복사했더니 주소에 `%20`, `%EC%95%88` 같은 **이상한 문자가 잔뜩 섞여** 있던 경험, 있으실 겁니다. 반대로 한글이 들어간 주소를 메신저로 보냈더니 **깨져서 안 열린** 적도 있을 것입니다. 이 모두가 **URL 인코딩**과 관련된 일입니다.

URL 인코딩은 어려운 개념이 아니라, **주소에 쓸 수 없는 문자를 안전한 형태로 바꾸는 약속**일 뿐입니다. 이 글에서는 URL 인코딩이 정확히 무엇이고, 왜 `%` 문자가 생기는지, 실제 변환 예시, 깨진 주소를 푸는 법, 그리고 두 번 인코딩 같은 흔한 실수까지 정리합니다.

## URL 인코딩이란

웹 주소(URL)에는 **쓸 수 있는 문자가 정해져** 있습니다. 영문, 숫자, 일부 기호(`-`, `_`, `.`, `~`)만 안전하게 통하고, **공백·한글·특수문자는 그대로 쓸 수 없습니다.** 그래서 이런 문자를 안전한 형태로 바꾸는 것이 URL 인코딩(퍼센트 인코딩)입니다.

원리는 단순합니다. 쓸 수 없는 문자를 **`%` + 16진수 코드**로 바꿉니다. 그래서 인코딩된 주소엔 `%`가 잔뜩 보이는 것입니다.

## 인코딩 전 / 후 — 실제 예시

```text
공백        →  %20
한글 "안"   →  %EC%95%88   (UTF-8 기준 3바이트)
&           →  %26
?           →  %3F
검색어 "맛집" →  %EB%A7%9B%EC%A7%91
```

예를 들어 `armes.co.kr/검색?q=맛집 추천` 은 다음처럼 인코딩됩니다:

```text
armes.co.kr/%EA%B2%80%EC%83%89?q=%EB%A7%9B%EC%A7%91%20%EC%B6%94%EC%B2%9C
```

이상해 보여도, 어떤 환경에서든 주소가 깨지지 않게 전달하기 위한 약속입니다.

## 인코딩과 디코딩

| 구분 | 방향 | 쓰는 때 |
| --- | --- | --- |
| 인코딩(Encode) | 사람이 읽는 주소 → `%` 형태 | 주소를 만들거나 공유할 때 |
| 디코딩(Decode) | `%` 형태 → 원래 주소 | `%` 범벅 주소가 무슨 뜻인지 확인할 때 |

## 언제 필요한가 — 실전 사용 예시

| 상황 | 이유 |
| --- | --- |
| 링크 공유 | 한글·공백 든 주소를 메신저·메일로 깨짐 없이 |
| 검색·파라미터 처리 | 검색어를 주소(`?q=`)에 담을 때 |
| API 요청 | 요청 주소에 값(한글·기호)을 넣을 때 |
| 광고·유입 분석 | `utm_` 파라미터에 캠페인명 담을 때 |

## ⚠️ 가장 흔한 실수 — 두 번 인코딩

이미 인코딩된 주소를 **또 인코딩**하면 `%`가 `%25`로 바뀌며 더 깨집니다. 이게 "분명 인코딩했는데 더 이상해졌다"의 원인입니다.

```text
원본        :  안
1번 인코딩   :  %EC%95%88     (정상)
2번 인코딩   :  %25EC%2595%2588  (깨짐 — % 가 %25로)
```

> 규칙: **인코딩은 딱 한 번.** 이미 `%XX`가 섞인 주소는 더 인코딩하지 말고, 헷갈리면 먼저 디코딩해 원본을 확인하세요.

## 알아두면 좋은 점

- **인코딩 기준은 UTF-8:** 한글 한 글자가 보통 `%XX%XX%XX` 세 덩이가 됩니다. 디코딩도 같은 기준이어야 안 깨집니다.
- **`+` 와 `%20`:** 공백은 보통 `%20`이지만, 일부 폼 전송에서는 `+`로 표현됩니다. 둘 다 공백을 뜻합니다.
- **브라우저 자동 처리:** 요즘 브라우저는 주소창의 한글을 자동 인코딩해 주지만, 코드·외부 전달 시엔 직접 인코딩이 안전합니다.

## 결론

URL 인코딩은 **주소에 쓸 수 없는 문자(공백·한글·특수문자)를 `%`+코드 형태로 바꾸는** 약속입니다. 깨진 주소는 디코딩으로 원래 모습을 확인하고, 공유할 주소는 인코딩으로 안전하게 만들면 됩니다. **두 번 인코딩만 피하면** 어렵지 않습니다.

## 자주 묻는 질문 (FAQ)

**Q. 주소에 보이는 `%20`은 무슨 뜻인가요?**
공백을 URL 인코딩한 형태입니다. 주소엔 공백을 그대로 쓸 수 없어 `%20`으로 바꿔 표현합니다.

**Q. 한글 주소는 왜 `%EC%95%88`처럼 길어지나요?**
한글 한 글자가 UTF-8에서 보통 3바이트라, 각 바이트가 `%XX`로 인코딩되어 세 덩이가 됩니다.

**Q. 인코딩했는데 주소가 더 깨졌어요.**
이미 인코딩된 주소를 또 인코딩한 경우입니다. `%`가 `%25`로 바뀌며 깨집니다. 먼저 디코딩해 원본으로 되돌린 뒤 한 번만 인코딩하세요.

**Q. 디코딩은 언제 쓰나요?**
`%` 범벅인 주소가 실제로 무엇인지 확인할 때 씁니다. 인코딩의 반대로, 사람이 읽는 원래 주소로 되돌립니다.

**Q. `+`와 `%20`은 같은 건가요?**
둘 다 공백을 뜻하지만 맥락이 다릅니다. 주소 경로에선 `%20`, 일부 폼 전송에선 `+`로 공백을 표현합니다.

**Q. 어떤 문자를 인코딩해야 하나요?**
공백·한글·`&`·`?`·`#`·`/` 같은 특수문자입니다. 영문·숫자·일부 기호(`-_.~`)는 그대로 둬도 됩니다.

**Q. 브라우저가 알아서 처리하면 직접 인코딩 안 해도 되나요?**
주소창에선 자동 처리되지만, 코드에서 주소를 만들거나 외부로 값을 전달할 때는 직접 인코딩해야 안전합니다.

**Q. 온라인 인코딩 도구에 민감한 값을 넣어도 되나요?**
입력값이 서버로 전송되는 도구라면 주의하세요. 토큰·개인정보가 든 주소는 브라우저 안에서만 처리되는 도구를 쓰는 게 안전합니다.

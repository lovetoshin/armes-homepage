API 응답을 받아 콘솔에 찍었더니 JSON이 **한 줄로 길게 뭉쳐** 도무지 어디가 어디인지 알 수 없던 경험, 개발하는 분이라면 다들 있으실 겁니다. 설정 파일, 로그, 외부 API 응답 — JSON은 전송 효율을 위해 공백 없이 압축된 채 오는 경우가 많습니다. 사람 눈으로는 거의 암호 수준입니다.

이때 **JSON 포맷터(Formatter, 정리 도구)** 가 그 뭉친 데이터를 줄바꿈과 들여쓰기로 **펼쳐서** 한눈에 보이게 해 줍니다. 단순히 보기 좋게만 하는 게 아니라, **문법 오류 위치까지 짚어** 줘서 디버깅 시간을 크게 줄여 줍니다. 이 글에서는 JSON 포맷의 개념, 실제 전/후 예시, 자주 만나는 오류, 그리고 안전하게 쓰는 법까지 정리합니다.

## JSON이란

JSON(제이슨)은 데이터를 주고받을 때 가장 널리 쓰는 형식입니다. **이름(key)과 값(value)이 짝을 이루는** 구조라, 사람과 컴퓨터 모두 이해하기 쉽습니다. 웹·앱·서버가 데이터를 교환하는 사실상 표준입니다.

다만 네트워크로 전송할 때는 용량을 줄이려 **공백 없이 한 줄로 압축(minify)** 해서 보냅니다. 그래서 받아서 열어 보면 읽기 어려운 것입니다.

## 포맷 전 / 후 — 실제로 이렇게 바뀝니다

**포맷 전 (압축된 한 줄):**

```json
{"user":{"id":1024,"name":"신지한","roles":["admin","seller"],"active":true,"profile":{"city":"서울","verified":false}}}
```

**포맷 후 (펼친 모습):**

```json
{
  "user": {
    "id": 1024,
    "name": "신지한",
    "roles": ["admin", "seller"],
    "active": true,
    "profile": {
      "city": "서울",
      "verified": false
    }
  }
}
```

같은 데이터지만, 펼친 쪽은 **어떤 값이 어디에 속하는지 계층이 한눈에** 보입니다. 반대로 펼친 JSON을 다시 한 줄로 **압축(minify)** 하는 것도 포맷터의 기능입니다.

## 포맷 vs 압축(minify) — 언제 무엇을 쓰나

| 구분 | 포맷(Beautify) | 압축(Minify) |
| --- | --- | --- |
| 목적 | 사람이 읽기 좋게 | 용량 줄여 전송 |
| 결과 | 줄바꿈·들여쓰기 | 공백 제거 한 줄 |
| 쓸 때 | 디버깅·검토·문서화 | API 응답·저장·배포 |
| 용량 | 큼 | 작음 |

## 자주 만나는 오류 (가장 중요)

JSON은 문법이 **엄격**해서 작은 실수 하나에도 전체가 오류 납니다. 포맷터는 오류 위치(몇 번째 줄)를 짚어 주므로 빠르게 고칠 수 있습니다.

| 오류 | 잘못된 예 | 올바른 예 |
| --- | --- | --- |
| 마지막 쉼표(trailing comma) | `["a","b",]` | `["a","b"]` |
| 작은따옴표 사용 | `{'name':'kim'}` | `{"name":"kim"}` |
| 키에 따옴표 누락 | `{name:"kim"}` | `{"name":"kim"}` |
| 괄호 짝 안 맞음 | `{"a":1` | `{"a":1}` |
| 값에 주석 | `{"a":1 //설명}` | (JSON은 주석 불가) |
| 후행 값 없음 | `{"a":}` | `{"a":null}` |

> JSON에서 가장 흔한 오류는 단연 **마지막 쉼표**와 **작은따옴표**입니다. 이 둘만 의심해도 절반은 잡힙니다.

## 실전 사용 예시

- **API 디버깅:** 서버 응답이 이상할 때, 한 줄 응답을 포맷해 어떤 필드가 빠졌는지 즉시 확인.
- **설정 파일 점검:** `package.json`, 각종 config 파일의 괄호·쉼표 오류를 저장 전에 검증.
- **로그 분석:** 로그에 박힌 JSON 덩어리를 펼쳐 문제 데이터 추적.
- **문서 작성:** API 명세서에 넣을 예시를 깔끔하게 정리.

## 관련 도구 비교 — 어디서 포맷할까

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| 온라인 포맷터 | 설치 없이 즉시 | 민감정보 주의 |
| 에디터 확장(VS Code 등) | 작업 흐름에 통합 | 설치·설정 필요 |
| 브라우저 콘솔(`JSON.parse`) | 빠름 | 손이 많이 감 |
| 명령줄(`jq`) | 자동화에 강함 | 학습 필요 |

가볍게 한두 번이면 **온라인 포맷터**가 가장 빠릅니다. 가입·설치 없이 브라우저에서 바로 쓰는 도구를 아르메스도 [ARMES Tools](/projects/tools)로 준비하고 있습니다.

## 안전하게 쓰기 (중요)

JSON에는 **API 키, 토큰, 개인정보** 같은 민감한 값이 담길 수 있습니다. 이런 데이터는 반드시 **브라우저 안에서만 처리되는(서버 전송 없는) 도구**에서 다루세요. 입력값이 외부 서버로 전송되는 도구라면 민감 데이터를 넣으면 안 됩니다.

JSON 안에는 Base64로 인코딩된 값이나 URL이 함께 들어 있는 경우가 많습니다. 그럴 땐 [Base64 인코딩·디코딩 쉽게 이해하기](/blog/base64-guide)와 [URL 인코딩이란? 깨진 주소 해결하기](/blog/url-encoder)를 함께 보면 도움이 됩니다. 그 밖의 개발용 도구는 [개발자용 온라인 도구 모음](/blog/dev-tools)과 [온라인 텍스트·개발자 도구 모음](/blog/online-dev-text-tools)에 정리했습니다.

## 결론

JSON 포맷은 뭉친 데이터를 **보기 좋게 펼치고, 문법 오류를 찾아** 주는 작업입니다. 디버깅엔 포맷(Beautify), 전송·배포엔 압축(Minify)으로 나눠 쓰면 됩니다. 오류는 **마지막 쉼표, 따옴표 종류, 괄호 짝** 이 셋만 신경 쓰면 대부분 해결됩니다. 그리고 민감한 값이 담긴 JSON은 처리 방식을 꼭 확인하고 쓰세요.

## 자주 묻는 질문 (FAQ)

**Q. JSON 포맷터는 무엇을 하는 도구인가요?**
한 줄로 압축된 JSON을 줄바꿈·들여쓰기로 펼쳐 읽기 쉽게 만들고, 문법 오류 위치를 짚어 주는 도구입니다. 반대로 펼친 JSON을 한 줄로 압축할 수도 있습니다.

**Q. 포맷(Beautify)과 압축(Minify)은 무엇이 다른가요?**
포맷은 사람이 읽기 좋게 펼치는 것, 압축은 공백을 없애 용량을 줄이는 것입니다. 디버깅엔 포맷, 전송·저장엔 압축을 씁니다.

**Q. JSON에서 가장 흔한 오류는 무엇인가요?**
마지막 항목 뒤의 쉼표(trailing comma)와 작은따옴표 사용입니다. JSON은 큰따옴표만 허용하고, 마지막 쉼표를 금지합니다.

**Q. JSON에 주석을 달 수 있나요?**
표준 JSON은 주석을 지원하지 않습니다. `//`나 `/* */`를 넣으면 오류가 납니다. 주석이 필요하면 별도 설명용 필드를 두세요.

**Q. 키(key)에도 따옴표가 필요한가요?**
네. JSON에서는 키와 문자열 값 모두 큰따옴표로 감싸야 합니다. `{name:"kim"}`은 오류, `{"name":"kim"}`이 정답입니다.

**Q. 온라인 포맷터에 민감한 데이터를 넣어도 되나요?**
입력값이 외부 서버로 전송되는 도구라면 안 됩니다. API 키·개인정보가 담긴 JSON은 브라우저 안에서만 처리되는 도구를 쓰세요.

**Q. 포맷터가 "Invalid JSON" 오류를 내는데 어디가 문제인지 모르겠어요.**
대부분 쉼표·따옴표·괄호 문제입니다. 포맷터가 알려 주는 줄 번호 근처를 보고, 마지막 쉼표와 작은따옴표부터 의심하세요.

**Q. 아주 큰 JSON도 포맷할 수 있나요?**
대부분 가능하지만, 매우 큰 파일은 브라우저가 느려질 수 있습니다. 이럴 땐 명령줄 도구(`jq`)나 에디터를 쓰는 게 안정적입니다.

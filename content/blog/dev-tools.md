개발이나 데이터 업무를 하다 보면 "이 변환, 빠르게 할 도구 없나?" 싶은 순간이 하루에도 여러 번입니다. JSON을 보기 좋게 정리하거나, 값을 Base64로 인코딩하거나, 색상 코드를 바꾸거나, 타임스탬프를 날짜로 바꾸는 일들입니다. 매번 코드를 짜거나 프로그램을 깔기엔 번거롭죠.

이런 작업은 대부분 **설치 없이 브라우저에서** 바로 끝납니다. 자주 쓰는 도구만 알아 두면 반복 작업 시간을 크게 줄일 수 있습니다. 이 글에서는 개발·실무에서 자주 쓰는 도구를 **용도별로 한곳에** 모으고, 각 도구가 어떤 일을 하는지(예시 포함), 그리고 민감 데이터를 안전하게 다루는 법까지 정리합니다.

## 자주 쓰는 개발자 도구 한눈에

| 분류 | 도구 | 하는 일 |
| --- | --- | --- |
| 데이터 | JSON 포맷 | 뭉친 JSON 펼치기·검증 |
| 인코딩 | Base64 | 데이터를 글자로 포장 |
| 인코딩 | URL 인코딩 | 주소 특수문자 처리 |
| 디자인 | 색상 코드 변환 | HEX ↔ RGB |
| 시간 | 타임스탬프 변환 | 숫자 시간 ↔ 날짜 |
| 보안 | 해시 생성 | 무결성 확인용 해시 |
| 텍스트 | 대소문자·중복 제거 | [텍스트 도구](/blog/text-tools) 참고 |

## 데이터 정리·변환

### JSON 포맷(정리)
한 줄로 뭉친 JSON을 보기 좋게 들여쓰기해 줍니다. 구조를 한눈에 파악할 수 있어 개발·디버깅에 필수입니다.

```text
[전] {"id":1,"tags":["a","b"]}
[후] {
       "id": 1,
       "tags": ["a", "b"]
     }
```

자세한 내용은 [JSON 포맷(정리)하는 법](/blog/json-format)에서 다룹니다.

### 인코딩/디코딩
- **Base64:** 데이터를 글자로 바꿔 전송할 때 씁니다(`ARMES` → `QVJNRVM=`). 원리는 [Base64 인코딩·디코딩 쉽게 이해하기](/blog/base64-guide)에.
- **URL 인코딩:** 주소에 들어가는 특수문자·한글을 안전하게 바꿉니다(`공백` → `%20`). [URL 인코딩이란?](/blog/url-encoder)에.

## 디자인·실무용

| 도구 | 예시 |
| --- | --- |
| 색상 코드 변환 | `#1D62F0` ↔ `rgb(29, 98, 240)` |
| 타임스탬프 변환 | `1750000000` ↔ `2025-06-15 ...` |
| 해시 생성 | 텍스트 → SHA-256 해시값 |

- **색상 코드 변환:** HEX와 RGB를 서로 바꿉니다. 디자인·퍼블리싱에서 자주 필요합니다.
- **타임스탬프 변환:** 숫자로 된 시간값(유닉스 타임)을 사람이 읽는 날짜로 바꿉니다. 로그 분석에 유용합니다.
- **해시 생성:** 텍스트·파일의 해시값을 만들어 변조 여부(무결성)를 확인합니다.

## 텍스트 관련

대소문자 변환, 중복 줄 제거, 글자 수 세기 같은 텍스트 작업은 [텍스트 도구 모음](/blog/text-tools)에 따로 정리했습니다. 전체 묶음은 [온라인 텍스트·개발자 도구 모음](/blog/online-dev-text-tools)에서도 볼 수 있습니다.

## ⚠️ 안전하게 쓰는 법 (개발자는 특히 중요)

개발 데이터에는 **API 키, 토큰, DB 접속정보, 고객 데이터**처럼 민감한 값이 섞이기 쉽습니다.

| 점검 | 이유 |
| --- | --- |
| 브라우저 안에서 처리되는가 | 입력값이 서버로 안 가면 유출 위험↓ |
| 회사 보안정책 확인 | 외부 도구 사용이 제한될 수 있음 |
| 키·토큰은 도구에 넣지 않기 | 실수로 외부 전송되면 사고 |

> 특히 **운영 API 키나 토큰을 아무 온라인 도구에 붙여넣는 것**은 사고로 이어질 수 있습니다. 민감 값은 브라우저 내 처리 도구를 쓰거나, 테스트용 더미 값으로 바꿔 다루세요.

가입·설치 없이 브라우저에서 바로 쓰는 개발자 도구 모음을 아르메스도 [ARMES Tools](/projects/tools)로 준비하고 있습니다.

## 결론

JSON 정리, 인코딩, 색상·시간·해시 변환 같은 개발 작업은 **설치 없이 브라우저에서** 빠르게 처리됩니다. 자주 쓰는 도구를 한곳에 모아 두면 반복 작업의 시간을 크게 아낄 수 있습니다. 다만 **API 키·토큰 같은 민감한 데이터**는 처리 방식을 꼭 확인하고 쓰세요.

## 자주 묻는 질문 (FAQ)

**Q. 개발자 온라인 도구는 설치가 필요 없나요?**
대부분 브라우저에서 바로 씁니다. JSON 포맷·인코딩·색상 변환 등은 페이지를 열어 입력만 하면 됩니다.

**Q. 운영 API 키를 온라인 도구에 넣어도 되나요?**
위험합니다. 입력값이 서버로 전송되는 도구라면 키가 유출될 수 있습니다. 민감 값은 브라우저 내 처리 도구를 쓰거나 더미 값으로 다루세요.

**Q. JSON 포맷 도구는 왜 필요한가요?**
API 응답이 한 줄로 뭉쳐 오면 읽기 어렵습니다. 포맷하면 구조가 보이고 문법 오류 위치까지 짚어 줘 디버깅이 빨라집니다.

**Q. Base64와 URL 인코딩은 무엇이 다른가요?**
Base64는 데이터를 글자로 포장하는 것, URL 인코딩은 주소에 못 쓰는 문자를 `%` 형태로 바꾸는 것입니다. 목적이 다릅니다.

**Q. 색상 코드는 왜 변환하나요?**
디자인 시안은 HEX(`#...`), 코드에선 RGB가 편할 때가 있어 서로 바꿔 씁니다. 변환 도구로 즉시 환산합니다.

**Q. 타임스탬프 변환은 언제 쓰나요?**
로그·DB의 시간이 숫자(유닉스 타임)로 저장된 경우, 사람이 읽는 날짜로 바꿔 확인할 때 씁니다.

**Q. 해시 생성은 무엇에 쓰나요?**
파일·텍스트가 변조되지 않았는지 확인(무결성 검증)할 때 씁니다. 단, 해시는 암호화가 아니라는 점을 기억하세요.

**Q. 여러 도구를 매번 따로 찾기 번거로워요.**
자주 쓰는 도구를 한곳에 모아 둔 도구 모음을 쓰면 편합니다. 즐겨찾기에 등록해 두는 것도 방법입니다.

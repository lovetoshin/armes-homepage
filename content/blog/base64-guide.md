개발이나 데이터를 다루다 보면 "Base64로 인코딩하라"는 말을 만납니다. 알 수 없는 긴 문자열이 바로 그것입니다. 어려워 보이지만 개념은 단순합니다. 이 글에서는 Base64가 무엇이고 왜 쓰는지, 어떻게 인코딩·디코딩하는지 쉽게 풀어 정리합니다.

## Base64란 무엇인가

Base64는 **어떤 데이터든 영문·숫자·기호 몇 가지로만 표현하는 방법**입니다. 그림이나 파일처럼 글자가 아닌 데이터도 Base64를 거치면 텍스트 문자열로 바뀝니다.

쉽게 비유하면, 어떤 물건이든 안전하게 우편으로 보내기 위해 **표준 상자에 다시 포장**하는 것과 같습니다. 내용은 그대로지만, 어디서든 문제없이 전달되는 형태로 바꾸는 것입니다.

## 왜 쓸까

데이터를 주고받는 통로 중에는 **글자만 안전하게 전달**되는 경우가 있습니다. 이미지 같은 비(非)문자 데이터를 그대로 보내면 깨질 수 있어, Base64로 글자처럼 바꿔 보냅니다. 대표적으로 이메일 첨부, 일부 데이터 전송, 웹페이지에 작은 이미지를 직접 담을 때 쓰입니다.

## 인코딩과 디코딩

- **인코딩:** 원본 데이터 → Base64 문자열로 바꾸기
- **디코딩:** Base64 문자열 → 원본 데이터로 되돌리기

온라인 도구에 원본을 넣으면 인코딩 결과를, Base64 문자열을 넣으면 디코딩 결과를 바로 보여 줍니다.

## 알아두면 좋은 점

- **암호화가 아닙니다.** Base64는 누구나 디코딩할 수 있어, 보안 수단이 아닙니다. 비밀번호를 Base64로만 "숨겼다"고 생각하면 위험합니다.
- **용량이 약간 늘어납니다.** 인코딩하면 원본보다 30% 정도 커집니다.
- **민감한 값 주의:** 토큰·키가 담긴 데이터는 신뢰할 수 있는, 브라우저 안에서 처리되는 도구에서 다루세요.

JSON 안에 Base64 값이 들어 있는 경우가 많으니 [JSON 포맷(정리)하는 법](/blog/json-format)과, 주소를 다룰 때 쓰는 [URL 인코딩이란? 깨진 주소 해결하기](/blog/url-encoder)도 함께 보면 도움이 됩니다. 그 밖의 도구는 [개발자용 온라인 도구 모음](/blog/dev-tools)에 정리했습니다.

## 정리

Base64는 **어떤 데이터든 안전하게 전달하기 위해 글자로 다시 포장**하는 방법입니다. 인코딩으로 바꾸고 디코딩으로 되돌리며, 암호화가 아니라는 점만 기억하면 됩니다. 개념만 잡으면 더 이상 알 수 없는 문자열에 당황할 일이 없습니다.

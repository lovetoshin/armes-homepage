개발이나 데이터를 다루다 보면 `aHR0cHM6Ly9hcm1lcy5jby5rcg==` 같은 **알 수 없는 긴 문자열**을 만납니다. 또 "이 값을 Base64로 인코딩해서 보내라"는 안내를 받기도 합니다. 처음엔 암호처럼 보이지만, 개념을 알면 허무할 만큼 단순합니다.

Base64는 **어떤 데이터든 영문·숫자 몇 가지 글자로만 다시 표현하는 방법**입니다. 이 글에서는 Base64가 정확히 무엇이고 왜 쓰는지, 실제 인코딩/디코딩 예시, 흔한 오해(암호화 아님!), 그리고 안전하게 쓰는 법까지 비전공자도 이해할 수 있게 풀어 정리합니다.

## Base64란 무엇인가

Base64는 그림·파일처럼 **글자가 아닌 데이터(바이너리)도 텍스트 문자열로 바꾸는** 방식입니다. 영문 대소문자(A–Z, a–z), 숫자(0–9), 그리고 `+`, `/` 두 기호 — 합쳐 **64글자**만 사용한다고 해서 Base64입니다.

쉽게 비유하면, 어떤 물건이든 안전하게 우편으로 보내려고 **규격 상자에 다시 포장**하는 것과 같습니다. 내용물은 그대로지만, 어디서든 문제없이 전달되는 형태로 겉모습만 바꾸는 것입니다.

## 인코딩 전 / 후 — 실제 예시

**원본 텍스트 → Base64 (인코딩):**

```text
원본 :  ARMES
Base64 :  QVJNRVM=
```

```text
원본 :  안녕하세요
Base64 :  7JWI64WV7ZWY7IS47JqU
```

거꾸로 `QVJNRVM=` 를 **디코딩**하면 다시 `ARMES`가 됩니다. 끝에 붙는 `=`는 길이를 맞추기 위한 **패딩** 기호입니다.

## 인코딩과 디코딩

| 구분 | 방향 | 예시 |
| --- | --- | --- |
| 인코딩(Encode) | 원본 → Base64 | `ARMES` → `QVJNRVM=` |
| 디코딩(Decode) | Base64 → 원본 | `QVJNRVM=` → `ARMES` |

온라인 도구에 원본을 넣으면 인코딩 결과를, Base64 문자열을 넣으면 디코딩 결과를 바로 보여 줍니다.

## 왜 쓸까 — 실전 사용 예시

데이터를 주고받는 통로 중에는 **글자(텍스트)만 안전하게 전달**되는 경우가 많습니다. 이미지 같은 비문자 데이터를 그대로 보내면 깨질 수 있어, Base64로 "글자처럼" 바꿔 보냅니다.

| 쓰는 곳 | 이유 |
| --- | --- |
| 이메일 첨부 | 옛 이메일 규약이 텍스트만 안전 전송 |
| 웹페이지 인라인 이미지 | 작은 아이콘을 파일 없이 코드에 직접 삽입(Data URL) |
| API 토큰 전달 | `Authorization` 헤더 등에 텍스트로 실어 보냄 |
| JSON 안에 파일 담기 | JSON은 텍스트라, 파일을 Base64로 넣음 |

## ⚠️ 가장 흔한 오해 — Base64는 암호화가 아닙니다

이게 이 글에서 **가장 중요한 부분**입니다.

| 오해 | 사실 |
| --- | --- |
| "Base64로 바꾸면 안전하게 숨겨진다" | ❌ 누구나 1초 만에 디코딩 가능 |
| "비밀번호를 Base64로 저장하면 보안된다" | ❌ 평문과 다름없음 |
| "암호화의 일종이다" | ❌ 그냥 **표현 방식 변환**일 뿐 |

Base64는 자물쇠가 아니라 **투명한 포장지**입니다. 누구나 풀어서 내용을 봅니다. **비밀번호·민감정보를 Base64로만 "숨겼다"고 믿는 것은 매우 위험**합니다. 진짜 보안이 필요하면 암호화(해시·AES 등)를 써야 합니다.

## 알아두면 좋은 점

- **용량이 약 33% 늘어납니다.** 원본 3바이트가 Base64 4글자가 되기 때문입니다. 작은 데이터엔 괜찮지만 큰 파일엔 부담.
- **URL용 변형이 있습니다.** `+`, `/`가 주소에서 문제 되어, URL-safe Base64는 `-`, `_`로 바꿔 씁니다.
- **민감한 값 주의:** 토큰·키가 담긴 데이터는 **브라우저 안에서만 처리되는** 도구에서 다루세요.

## 결론

Base64는 **어떤 데이터든 글자로 다시 포장해 안전하게 전달**하는 방법입니다. 인코딩으로 바꾸고 디코딩으로 되돌리면 끝입니다. 딱 하나만 기억하세요 — **Base64는 암호화가 아니라 포장**입니다. 개념만 잡으면 더 이상 알 수 없는 문자열에 당황할 일이 없습니다.

## 자주 묻는 질문 (FAQ)

**Q. Base64는 한마디로 무엇인가요?**
글자가 아닌 데이터(이미지·파일 등)를 영문·숫자 64글자만으로 표현해 텍스트처럼 다루게 해 주는 방식입니다.

**Q. Base64로 인코딩하면 데이터가 안전해지나요?**
아닙니다. 누구나 즉시 디코딩할 수 있어 보안 효과가 전혀 없습니다. 보안이 필요하면 암호화를 써야 합니다.

**Q. 끝에 붙는 `=` 기호는 무엇인가요?**
길이를 4의 배수로 맞추기 위한 패딩 기호입니다. 원본 길이에 따라 0~2개가 붙습니다.

**Q. 인코딩하면 용량이 왜 늘어나나요?**
원본 3바이트가 Base64 4글자로 표현되기 때문에 약 33% 커집니다. 큰 파일을 Base64로 담을 때는 이 점을 고려하세요.

**Q. 주소(URL)에 Base64를 넣었더니 깨져요.**
일반 Base64의 `+`, `/` 기호가 URL에서 문제를 일으킵니다. 이럴 땐 `-`, `_`를 쓰는 URL-safe Base64를 사용하세요.

**Q. 한글도 Base64로 인코딩되나요?**
됩니다. 다만 한글은 보통 UTF-8로 먼저 바이트로 바뀐 뒤 인코딩되므로, 디코딩 시 인코딩 기준(UTF-8)이 같아야 깨지지 않습니다.

**Q. 비밀번호를 Base64로 저장해도 되나요?**
절대 안 됩니다. 평문 저장과 다름없습니다. 비밀번호는 해시(예: bcrypt) 처리해야 합니다.

**Q. 온라인 Base64 도구에 민감한 값을 넣어도 되나요?**
입력값이 서버로 전송되는 도구라면 안 됩니다. 토큰·키는 브라우저 안에서만 처리되는 도구를 쓰세요.

如果你曾經把API回應貼到主控台，看到的是**一行沒有任何空白的JSON長串**，那種困惑一定歷歷在目。設定檔、日誌、第三方API回應——JSON在網路傳輸時為了減少資料量，通常會去除所有空白壓縮成一行。對人眼來說，這幾乎是天書。

這時候，**JSON格式化工具（Formatter/Beautifier）** 就能將那團壓縮的資料用換行和縮排**展開**，讓結構一目了然。它不僅僅是讓資料「好看」，更重要的是能**精確指出語法錯誤所在的行號**，大大節省除錯時間。本文將介紹JSON格式化的概念、實際前後對比示例、常見錯誤類型，以及安全使用的注意事項。

## 什麼是JSON

JSON（JavaScript Object Notation，JavaScript物件表示法）是資料交換中使用最廣泛的格式。其**鍵（key）與值（value）配對**的結構，使人和電腦都易於理解。它是網頁、行動應用程式和伺服器之間資料交換的事實標準。

但在網路傳輸時，為了減少資料量，JSON通常會被**壓縮（minify）成一行**，去除所有空白後傳送。這就是為什麼接收到的JSON看起來那麼難以閱讀。

## 格式化前後對比——實際效果

**格式化前（壓縮成一行）：**

```json
{"user":{"id":1024,"name":"신지한","roles":["admin","seller"],"active":true,"profile":{"city":"서울","verified":false}}}
```

**格式化後（展開後的樣子）：**

```json
{
  "user": {
    "id": 1024,
    "name": "신지한",
    "roles": ["admin", "seller"],
    "active": true,
    "profile": {
      "city": "서울",
      "verified": false
    }
  }
}
```

同樣的資料，展開後**哪個值屬於哪一層級一目了然**。反過來，格式化工具也可以將展開的JSON重新**壓縮（minify）**成一行。

## 格式化 vs 壓縮（minify）——分別在什麼時候用

| 區別 | 格式化（Beautify） | 壓縮（Minify） |
| --- | --- | --- |
| 目的 | 方便人類閱讀 | 減少體積以便傳輸 |
| 結果 | 換行+縮排 | 去除空白後的一行 |
| 使用場景 | 除錯、審查、文件撰寫 | API回應、儲存、部署 |
| 檔案大小 | 較大 | 較小 |

## 常見錯誤（最重要的部分）

JSON的語法**非常嚴格**，一個小小的失誤就會導致整個檔案報錯。格式化工具會指出錯誤所在的行號，幫助快速定位問題。

| 錯誤類型 | 錯誤示例 | 正確示例 |
| --- | --- | --- |
| 結尾多餘逗號（trailing comma） | `["a","b",]` | `["a","b"]` |
| 使用單引號 | `{'name':'kim'}` | `{"name":"kim"}` |
| 鍵名缺少引號 | `{name:"kim"}` | `{"name":"kim"}` |
| 括號不匹配 | `{"a":1` | `{"a":1}` |
| 值中包含註解 | `{"a":1 //說明}` | （JSON不支援註解） |
| 值為空 | `{"a":}` | `{"a":null}` |

> JSON中最常見的錯誤無疑是**結尾多餘逗號**和**使用單引號**。先排查這兩個，就能解決一半的問題。

## 實際使用場景

- **API除錯：** 伺服器回應異常時，將一行回應格式化後，立即查看哪個欄位缺失或有誤。
- **設定檔檢查：** 儲存前驗證`package.json`等設定檔中的括號和逗號錯誤。
- **日誌分析：** 將日誌中嵌入的JSON資料塊展開，追蹤問題資料。
- **文件撰寫：** 將JSON示例整理得乾淨清晰，便於寫入API文件。

## 安全使用須知（重要）

JSON中常常包含**API金鑰、存取權杖、個人資訊**等敏感資料。處理這類資料時，務必使用**僅在瀏覽器本機處理、不將資料傳送至外部伺服器**的工具。如果工具會將輸入內容上傳至遠端伺服器，請勿在其中輸入敏感資料。

JSON資料中經常包含Base64編碼的值或URL。遇到這種情況，可以參考[Base64編解碼輕鬆理解](/blog/base64-guide)和[什麼是URL編碼？修復亂碼網址](/blog/url-encoder)。其他開發者工具請參考[開發者常用線上工具合集](/blog/dev-tools)和[線上文字與開發者工具合集](/blog/online-dev-text-tools)。

## 總結

JSON格式化就是將壓縮的資料**展開成易讀結構，並找出語法錯誤**的過程。除錯和審查用格式化（Beautify），傳輸和部署用壓縮（Minify）。錯誤方面，只需注意**結尾多餘逗號、引號類型和括號匹配**這三點，大多數問題都能迎刃而解。另外，使用工具前務必確認其處理敏感資料的方式。

## 常見問題（FAQ）

**Q. JSON格式化工具是做什麼的？**
它將壓縮成一行的JSON用換行和縮排展開，使其便於閱讀，並指出語法錯誤所在位置。反過來也可以將展開的JSON壓縮成一行。

**Q. 格式化（Beautify）和壓縮（Minify）有什麼區別？**
格式化是為了方便人類閱讀而展開資料，壓縮是去除空白以減少體積。除錯用格式化，傳輸和儲存用壓縮。

**Q. JSON中最常見的錯誤是什麼？**
最後一個元素後面的多餘逗號（trailing comma）和使用單引號。JSON只允許使用雙引號，且禁止結尾逗號。

**Q. JSON中可以加註解嗎？**
標準JSON不支援註解。加入`//`或`/* */`會導致報錯。如需備註說明，請使用單獨的說明欄位。

**Q. 鍵名也需要加引號嗎？**
需要。在JSON中，鍵名和字串值都必須用雙引號括起來。`{name:"kim"}`是錯誤的，`{"name":"kim"}`才正確。

**Q. 可以將敏感資料放入線上格式化工具嗎？**
如果該工具會將輸入內容傳送至外部伺服器，則不可以。包含API金鑰或個人資訊的JSON，請使用僅在瀏覽器本機處理的工具。

**Q. 格式化工具提示「Invalid JSON」，但不知道哪裡出了問題。**
通常是逗號、引號或括號的問題。查看工具指出的行號附近，優先排查結尾多餘逗號和單引號。

**Q. 非常大的JSON檔案也能格式化嗎？**
大多數情況下可以，但檔案過大時瀏覽器可能會變慢。遇到這種情況，建議使用命令列工具（`jq`）或程式碼編輯器，更加穩定。

你有沒有複製過一個連結，發現網址裡**混滿了 `%20`、`%EC%95%88` 這樣的奇怪字元**？或者把含有中文的網址透過通訊軟體發給別人，結果**變成亂碼打不開**？這些情況都與 **URL 編碼**有關。

URL 編碼其實並不複雜，它只是**把網址中無法使用的字元轉換成安全格式的一種約定**。本文將詳細介紹 URL 編碼是什麼、為什麼會出現 `%` 字元、實際轉換範例、如何解開亂碼網址，以及重複編碼這種常見錯誤。

## 什麼是 URL 編碼

網址（URL）對**可使用的字元有明確規定**。只有英文字母、數字和少數符號（`-`、`_`、`.`、`~`）可以安全使用，**空格、中文字元和特殊符號不能直接出現在網址中**。URL 編碼（百分號編碼）就是將這些字元轉換為安全格式的方法。

原理很簡單：將不可用的字元轉換為 **`%` + 十六進位代碼**。這就是為什麼編碼後的網址裡充滿了 `%` 符號。

## 編碼前後 — 實際範例

```text
空格           →  %20
中文「安」      →  %E5%AE%89   （UTF-8 共 3 位元組）
&              →  %26
?              →  %3F
搜尋詞「美食」  →  %E7%BE%8E%E9%A3%9F
```

例如，`armes.co.kr/搜尋?q=美食 推薦` 編碼後變為：

```text
armes.co.kr/%E6%90%9C%E5%B0%8B?q=%E7%BE%8E%E9%A3%9F%20%E6%8E%A8%E8%96%A6
```

看起來很奇怪，但這正是為了確保網址在任何環境下都能正確傳輸的約定。

## 編碼與解碼

| 類型 | 方向 | 使用時機 |
| --- | --- | --- |
| 編碼（Encode） | 人類可讀地址 → `%` 格式 | 建立或分享網址時 |
| 解碼（Decode） | `%` 格式 → 原始地址 | 需要讀懂滿是 `%` 的網址時 |

## 什麼情況下需要用 — 實際使用場景

| 場景 | 原因 |
| --- | --- |
| 分享連結 | 將含中文或空格的網址透過訊息/郵件無損傳輸 |
| 搜尋/參數處理 | 將搜尋詞嵌入網址（`?q=`）時 |
| API 請求 | 在請求網址中包含中文或特殊字元時 |
| 廣告/流量分析 | 在 `utm_` 參數中嵌入推廣活動名稱時 |

## ⚠️ 最常見的錯誤 — 重複編碼

對**已經編碼過的網址再次編碼**，`%` 會變成 `%25`，導致網址更加混亂。這就是「明明編碼了，結果更亂」的原因。

```text
原始          :  安
編碼一次      :  %E5%AE%89     （正常）
編碼兩次      :  %25E5%2598%25AE%2589  （亂碼 — % 變成了 %25）
```

> 規則：**只編碼一次。** 如果網址中已經有 `%XX`，就不要再編碼了。如果搞不清楚，先解碼還原原始內容，再重新編碼一次。

## 補充知識

- **編碼標準是 UTF-8：** 一個中文字元通常會變成三組 `%XX`。解碼時也要用同樣的標準，否則會出現亂碼。
- **`+` 和 `%20`：** 空格通常用 `%20` 表示，但在某些表單提交中會用 `+` 來表示空格。兩者都代表空格。
- **瀏覽器自動處理：** 現代瀏覽器會自動編碼網址列中的中文字元，但在程式碼中建構網址或對外傳遞參數時，手動編碼更安全。

## 總結

URL 編碼是**將網址中不可用的字元（空格、中文、特殊字元）轉換為 `%` + 代碼格式**的約定。遇到亂碼網址就解碼還原，需要分享的網址就編碼後再發。**只要避免重複編碼**，就不會有什麼難度。

## 常見問題（FAQ）

**Q. 網址裡的 `%20` 是什麼意思？**
是空格的 URL 編碼形式。因為空格不能直接出現在網址中，所以用 `%20` 來表示。

**Q. 中文字元為什麼會變成 `%EC%95%88` 這樣很長的形式？**
一個中文字元在 UTF-8 編碼中通常佔 3 個位元組，每個位元組會被編碼為 `%XX`，因此會有三組。

**Q. 我編碼了網址，反而更亂了。**
這是因為對已經編碼過的網址又編碼了一次。`%` 變成了 `%25` 導致更加混亂。請先解碼還原為原始內容，再重新編碼一次。

**Q. 什麼時候用解碼？**
當你想搞清楚一個滿是 `%` 的網址實際是什麼內容時使用。它是編碼的反向操作，將網址還原為人類可讀的形式。

**Q. `+` 和 `%20` 是一樣的嗎？**
兩者都代表空格，但使用情境不同。在 URL 路徑中用 `%20`，在某些表單提交中用 `+` 來表示空格。

**Q. 哪些字元需要編碼？**
空格、中文字元、`&`、`?`、`#`、`/` 等特殊字元都需要編碼。英文字母、數字和少數符號（`-_.~`）可以保持不變。

**Q. 瀏覽器會自動處理，還需要手動編碼嗎？**
在網址列中瀏覽器會自動處理，但在程式碼中建構網址或向外部傳遞參數時，手動編碼更安全。

**Q. 在線上編碼工具中貼上敏感內容安全嗎？**
如果工具會將輸入上傳至伺服器，就需要注意。含有權杖或個人資料的網址，請只使用在瀏覽器本機處理的工具。

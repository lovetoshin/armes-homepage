## 資料整理與轉換

### JSON 格式化
將壓縮成一行的 JSON 展開並加入縮排，讓結構一目了然，是開發和除錯的必備工具。

```text
[處理前] {"id":1,"tags":["a","b"]}
[處理後] {
           "id": 1,
           "tags": ["a", "b"]
         }
```

詳細介紹請參考[JSON 格式化（整理）方法](/blog/json-format)。

### 編碼 / 解碼
- **Base64：** 將資料轉換為文字字串以便傳輸（`ARMES` → `QVJNRVM=`）。原理說明請參考[輕鬆理解 Base64 編碼與解碼](/blog/base64-guide)。
- **URL 編碼：** 將 URL 中的特殊字元和中文等安全處理（`空格` → `%20`）。詳見[什麼是 URL 編碼？](/blog/url-encoder)。

## 設計與日常工作

| 工具 | 範例 |
| --- | --- |
| 顏色代碼轉換 | `#1D62F0` ↔ `rgb(29, 98, 240)` |
| 時間戳記轉換 | `1750000000` ↔ `2025-06-15 ...` |
| 雜湊產生 | 文字 → SHA-256 雜湊值 |

- **顏色代碼轉換：** 在 HEX 和 RGB 之間相互轉換，設計和前端開發中經常用到。
- **時間戳記轉換：** 將數字格式的時間值（Unix 時間戳記）轉換為人類可讀的日期，日誌分析時非常實用。
- **雜湊產生：** 為文字或檔案產生雜湊值，用於確認內容是否被竄改（完整性驗證）。

## ⚠️ 安全使用指南（開發者尤其重要）

開發資料中往往混有 **API 金鑰、Token、資料庫連線資訊、使用者資料**等高度敏感的內容。

| 檢查項目 | 原因 |
| --- | --- |
| 是否在瀏覽器本機處理 | 輸入內容不上傳伺服器，外洩風險大幅降低 |
| 確認公司資安規定 | 部分公司禁止使用外部線上工具 |
| 金鑰和 Token 不要貼進工具 | 一旦意外上傳，可能引發資安事件 |

> 特別提醒：**將正式環境 API 金鑰或 Token 隨意貼到線上工具中**，存在嚴重的資安風險。敏感資料請使用瀏覽器本機處理的工具，或用測試用的假資料替代。

## 常見問題（FAQ）

**Q. 開發者線上工具真的不需要安裝嗎？**
大部分直接在瀏覽器中執行。JSON 格式化、編碼、顏色轉換等，開啟頁面、貼上內容即可使用。

**Q. 可以把正式環境 API 金鑰貼到線上工具裡嗎？**
有風險。如果工具會將輸入內容上傳伺服器，金鑰可能外洩。請使用瀏覽器本機處理的工具，或用測試用假資料代替。

**Q. 為什麼需要 JSON 格式化工具？**
API 回應往往是壓縮成一行的 JSON，幾乎無法直接閱讀。格式化後結構清晰可見，語法錯誤的位置也能一目了然，除錯效率大幅提升。

**Q. Base64 和 URL 編碼有什麼區別？**
Base64 是將資料打包成文字字串，URL 編碼是將 URL 中不允許的字元轉換為 `%` 形式。用途不同。

**Q. 為什麼要轉換顏色代碼？**
設計稿常用 HEX（`#...`），程式碼裡有時用 RGB 更方便，互相轉換時用轉換工具即時換算。

**Q. 時間戳記轉換在什麼時候用？**
當日誌或資料庫中的時間以純數字（Unix 時間戳記）儲存時，轉換成人類可讀的日期來查看。

**Q. 雜湊產生有什麼用？**
用於確認檔案或文字是否被竄改（完整性驗證）。注意：雜湊不等於加密。

**Q. 每次分別去找不同工具太麻煩了。**
使用將常用工具集中到一處的工具合集就能解決。收藏一個書籤，效率大幅提升。

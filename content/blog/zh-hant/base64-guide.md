做開發或處理資料時，經常會遇到 `aHR0cHM6Ly9hcm1lcy5jby5rcg==` 這樣**看不懂的長字串**。有時還會收到「請將此值進行 Base64 編碼後發送」的說明。初看像密碼，但理解原理之後會發現，其實簡單得讓人有點意外。

Base64 是**一種將任何資料都用幾十個英文字母和數字重新表示的方法**。本文將用非技術人員也能看懂的語言，解釋 Base64 究竟是什麼、為什麼使用，並透過實際示例說明編碼與解碼，澄清最常見的誤解（不是加密！），以及安全使用的方法。

## Base64 是什麼

Base64 是一種將圖片、檔案等**非文字資料（二進位資料）轉換為文字字串**的方法。它只使用英文大小寫字母（A–Z、a–z）、數字（0–9）以及 `+`、`/` 兩個符號——共 **64 個字元**，因此得名 Base64。

打個比方：就像為了安全地透過郵寄發送任何物品，**將其重新裝進標準尺寸的紙箱**一樣。內容物不變，只是把外觀換成任何地方都能無障礙傳遞的形式。

## 編碼前後 — 實際示例

**原始文字 → Base64（編碼）：**

```text
原始 :  ARMES
Base64 :  QVJNRVM=
```

```text
原始 :  你好
Base64 :  5L2g5aW9
```

反過來，將 `QVJNRVM=` **解碼**，就能還原為 `ARMES`。末尾的 `=` 是用於補齊長度的**填充符號**。

## 編碼與解碼

| 類別 | 方向 | 示例 |
| --- | --- | --- |
| 編碼（Encode） | 原始資料 → Base64 | `ARMES` → `QVJNRVM=` |
| 解碼（Decode） | Base64 → 原始資料 | `QVJNRVM=` → `ARMES` |

在線上工具中輸入原始內容，即可得到編碼結果；輸入 Base64 字串，即可立即得到解碼結果。

## 為什麼使用 — 實際使用場景

資料傳輸通道中，很多情況下**只能安全傳遞文字（文本）**。直接發送圖片等非文字資料可能導致內容損毀，因此先將其轉換為「類似文字」的形式再發送。

| 使用場景 | 原因 |
| --- | --- |
| 電子郵件附件 | 舊版郵件協定只能安全傳輸文字 |
| 網頁內嵌圖片 | 將小圖示不借助外部檔案直接嵌入程式碼（Data URL） |
| API 令牌傳輸 | 透過 `Authorization` 等請求標頭以文字形式傳遞 |
| JSON 中嵌入檔案 | JSON 是文字格式，檔案需先轉換為 Base64 嵌入 |

## ⚠️ 最常見的誤解 — Base64 不是加密

這是本文**最重要的部分**。

| 誤解 | 事實 |
| --- | --- |
| 「轉換為 Base64 就安全地隱藏了資料」 | ❌ 任何人 1 秒內即可解碼 |
| 「用 Base64 儲存密碼就安全了」 | ❌ 與明文儲存沒有區別 |
| 「它是一種加密方式」 | ❌ 只是**表示形式的轉換**而已 |

Base64 不是鎖，而是**透明的包裝紙**。任何人都可以打開查看內容。**認為「用 Base64 就能安全隱藏」是非常危險的想法。**真正需要安全保護時，必須使用加密技術（雜湊、AES 等）。

## 需要了解的幾點

- **資料大小會增加約 33%。**原始 3 個位元組的資料會變成 4 個 Base64 字元。小資料問題不大，但大檔案需要注意。
- **有 URL 安全版本。**`+`、`/` 在 URL 中會產生問題，URL 安全的 Base64 會將其替換為 `-`、`_`。
- **注意敏感資料：**包含令牌或金鑰的資料，請在**僅在瀏覽器內部處理**的工具中操作，不要上傳至伺服器。

## 總結

Base64 是**將任何資料重新打包為文字以便安全傳輸**的方法。編碼轉換，解碼還原，就是這麼簡單。記住一件事：**Base64 是包裝，不是加密。**理解了這個概念，再遇到看不懂的字串就不會慌張了。

## 常見問題（FAQ）

**Q. Base64 用一句話來說是什麼？**
將圖片、檔案等非文字資料用 64 個英文字元表示，使其能像純文字一樣處理的方法。

**Q. 用 Base64 編碼資料後資料會變安全嗎？**
不會。任何人都可以立即解碼，沒有任何安全效果。需要安全保護時，必須使用加密技術。

**Q. 末尾的 `=` 符號是什麼？**
用於將總長度補齊為 4 的倍數的填充符號。根據原始資料的長度，可能出現 0～2 個。

**Q. 編碼後資料大小為什麼會增加？**
因為原始 3 個位元組會表示為 4 個 Base64 字元，大小增加約 33%。在大檔案中嵌入 Base64 時需要考慮這一點。

**Q. 在 URL 中放了 Base64，結果亂碼了。**
普通 Base64 中的 `+`、`/` 符號在 URL 中會引起問題，請改用以 `-`、`_` 替代的 URL 安全 Base64。

**Q. 中文也能進行 Base64 編碼嗎？**
可以。中文通常先透過 UTF-8 轉換為位元組，再進行編碼。解碼時編碼方式（UTF-8）必須一致，否則會出現亂碼。

**Q. 可以用 Base64 儲存密碼嗎？**
絕對不行。與明文儲存沒有區別。密碼必須使用雜湊（如 bcrypt）處理。

**Q. 可以在線上 Base64 工具中輸入敏感資料嗎？**
如果該工具會將輸入發送至伺服器，則不行。令牌和金鑰請使用僅在瀏覽器內部處理的工具。
